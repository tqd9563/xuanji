璇玑 · 思考过程呈现方案

针对派发台（Dispatch）新增「模型思考过程」展示。以下三个方案共用同一条设计原则： 思考不是数据，所以它不发光——全部走中性色阶（faint / muted）， 唯一的结构记号是左侧 1px 竖线；彩色只留给工具卡的函数名和用户消息的翡翠底， 保证思考块永远退到助手正文之后的第二层级。

原型如实反映的两个限制： ① 下方思考文本是英文——SDK 的 display: 'summarized' 返回模型自写的英文摘要，不是逐字思考原文，也不保证中文； ② 思考文本只有开关打开后的新会话才有，历史会话回放（会话页 / 定时任务页）永远是空的，所以本方案只作用于派发台实时流。

方案 B · 流式浮现，答完自动收起

推荐

思考中默认展开并逐字流出，竖线随之呼吸；模型开始输出正式回答的一刻，思考块自动坍缩成一行， 留下耗时摘要，可随时点开回看。这是 Claude Code 终端的行为，也最贴合璇玑「观象台」的气质—— 过程可见但不留痕，滚动回顾时视线不被大段灰字打断。

方案 A · 始终折叠，与工具卡同族

最省事

思考块从头到尾都是一行，形态与工具卡完全一致，想看才点开。 好处是消息流永远紧凑、实现最简单（直接抄 ToolCard）； 代价是思考中你只能看到「思考中…」，看不到它在想什么，实时感受损失最大。

方案 C · 常驻幽灵轨，不可折叠

信息最全 / 最吵

思考文本永远铺开，靠灰度和左竖线压到背景层，不提供折叠。 适合把璇玑当「模型行为观察窗」用——一眼看全推理链； 代价是长会话滚动距离翻倍，且英文思考混在中文回答里，阅读节奏会被反复打断。

边界状态

按推荐方案 B 的形态，列出必须处理的四种非典型状态。

模型没有思考（adaptive 判定为简单任务）

好的，已帮你重启。

不渲染任何思考块，也不留占位。实测简单问题（如「农夫过河」）opus-5 直接零思考。

思考很长（>3000 字）

Let me reconsider the whole dispatch lifecycle. There are three places where a session can die without a model error, and I want to rule them out in order of likelihood rather than guessing…

展开态给 max-height + 底部渐隐，再点一次「展开全文」。避免单条思考顶掉整屏。

多轮思考（工具调用之间反复思考）

每段思考独立成块、独立计时，不合并。与工具卡交替出现，天然构成推理时间线。

历史会话回放

（无思考块）

会话页 / 定时任务页的回放不加思考块。 磁盘实测：40 个最新会话共 2158 个思考块，2119 个明文为空，加了也只是空气泡。
