Weekly 限额的 Fable 单独配比 · 派发页状态条

Agent SDK 的 usage 接口除 seven_day(all models)外还下发按模型桶拆分的周窗口(model_scoped[],标签如 Fable)。 两个窗口共用同一个重置时刻,但利用率独立——Fable 往往烧得更快。 下面三个方案演示同一组数值:Context 34%、Usage 62%(2h41m)、Weekly all 58%、Fable 84%(同为 3d4h 后重置,窗口时间已过 62%)。 芯片语法沿用现行方案(10px 刻度轨:填充=已用,亮刻度=此刻在窗口中的位置);紫色(--violet)与模型下拉同源,只作模型身份标识,填充色仍按 50/75 阈值取玉/琥珀/红。 服务端未下发 Fable 数据时,新增部分整体隐藏,回退为现状三条。

方案 B · Weekly 合并双轨

推荐

两个周窗口共用一个重置时刻,本就该是同一个芯片:上轨 8px 是 all models,下轨 5px 是 Fable,右侧两个数值上下对齐(Fable 值恒紫小字),倒计时只写一遍。 两轨同刻度线,上下一比即知「Fable 烧得比大盘快多少」。 横向占用只比现状多约 40px;代价是芯片长高 5px、下轨偏细(但它是次级信息,数值兜底)。
