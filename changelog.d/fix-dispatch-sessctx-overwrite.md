### 修复

- **派发页会话名被当次输入短暂顶替**：输入框上方的会话标识 `sessCtx` 在每次 `submit()` 都会判断「是否续接」来决定要不要用 prompt 占位命名，但漏判了「会话名已通过 attach/续接建立」的情形——从会话看板 attach 存活会话、或续接会话发第二条及以后的消息时，`resumeInfo` 为 null 但 `sessCtx` 已有正确名称，仍会被当次输入的 prompt 覆盖，直到切回会话页重新 attach（看板带回真实 `name`）才恢复；同时 `id: null` 还会连带抹掉已显示的会话 id 短码。现改为仅当 `sessCtx` 尚未建立（真正的第一条消息）时才用 prompt 占位命名，已建立的会话标识不再被后续发送覆盖。
