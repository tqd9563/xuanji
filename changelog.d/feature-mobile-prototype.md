### 修复
- **派发页移动端状态条挤压**：会话标识(sess-ctx)与用量条(Context/Usage/Weekly)、agent 状态三段挤在同一行导致用量条被推出可视区、要横滑才看得见。移动端把会话标识挪进消息区顶部(随内容滚动),状态条独占一行只放用量条 + agent 状态;发送按钮在移动端改图标(44×44 方形触控区),不再是被「转后台」开关和提示文字挤扁到显示不全的文字按钮。桌面布局不变。
- **派发页在部分安卓内嵌浏览器里发送按钮被顶到底部导航条后面**：真机(超级 App 内置浏览器,非独立 Safari/Chrome)反馈发送按钮仍看不清,根因是该类 WebView 对 `100dvh` 支持缺失或失真,派发页高度计算 `calc()` 整体失效,内容撑爆容器把输入框挤到我们自己的底部 tab 栏后面。三层修复:① `.chat` 补上经典 flexbox 修复 `min-height: 0`,即使高度计算完全失效也不会撑爆父容器(已用 `height:auto` 强制模拟验证);② 派发页高度改用 `100vh → 100dvh → --vh` 三级递进兜底,后者覆盖前者;③ 新增 JS 用 `window.innerHeight` 实测写入 `--vh` CSS 变量(跨内核一致性远好于任何 CSS 视口单位,是此类问题的标准解法),随 resize/orientationchange 更新。
- **派发页输入框底部在真机上仍被 tab 栏吞掉(真根因)**：上一条修复后 Chrome 真机复测仍复现——高度计算其实一直正确,真根因是 960px 断点遗留的 `.chat { min-height: 380px }` 在 ≤430px 同样生效且盖过 `min-height: 0`,聊天区拒绝收缩,内容(≈580px)硬撑爆固定高度容器(视口 657px 时仅 451px),把 composer 底部与 term-line 挤到 tab 栏后面;此前 844px 高的模拟视口恰好容得下,未暴露。修复:≤430px 块中和该遗留规则(`min-height: 0; max-height: none`)。已按用户手机真实视口(360×657)复现→修复→重跑复现路径验证,并回归 390×844、360×500(模拟键盘弹出)与带真实消息内容的续接会话(chat 内部滚动)三种场景。
- **回顾页项目行整页横向溢出**：`.rv-proj-head`(项目 chip + 元信息 + 成本三段同行、不换行)在 390px 视口撑到 464px,导致整页横滚、热力图与统计被裁出屏外。改为 chip+成本一行、元信息独占一行。
- **回顾/定时/派发三处移动端还是桌面残留样式**：回顾页顶部统计从桌面版一行文字改为原型规定的 stat-grid 2×2 卡片(prototype-mobile.html #v-review/#v-home 的既有设计,此前未接入);定时任务详情里的"运行历史"从固定列宽桌面表格改紧凑单行卡片流;派发页空态三个快捷建议 chip 补到 ≥44px 触控区(此前约 35px,原型未覆盖到的桌面遗留元素)。
- **「更多」二级菜单缺壁纸入口**：桌面壁纸设置面板本身不动,移动端按原型 stub 行为补一行「壁纸」+ 当前状态摘要,点击 toast 提示"移动端后续迭代",不強行搬桌面弹层过来。
