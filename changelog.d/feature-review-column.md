### 新增
- **验收中列**：会话看板新增「验收中」列。跑完且有新产出的会话默认落入此列，只有显式处置（继续 / 挂起 / 归档）才离开；打开回放只熄灭「待验收」角标、卡片不再挪列，解决已读未处置的卡片沉入空闲、越积越多的问题。卡片脚部与回放抽屉底部都提供三个处置按钮。
- **挂起处置**：`PUT/DELETE /api/sessions/:id/suspend`，落 `session_suspends` 表。挂起 = 看过了暂不处理，卡片回空闲并标「已挂起」；会话之后一旦有新产出，挂起自动失效、卡片回验收中，不会把新进展一起埋掉。

### 变更
- **看板列序与空闲降级**：列序改为 运行中 / 等待输入 / 验收中 / 空闲 / 已完成。「空闲」降级为停车场——两行紧凑卡 + 默认折叠（只展示最近 3 条），注意力让位给验收中；移动端 tab 同步新增「验收中」。
- **验收中启用基线**：功能首次运行时钉住当前时刻并持久化，只有产出晚于基线的会话才进验收中，历史存量不会在上线当天集体涌入。
- **状态色扩到六色**：紫罗兰在原有「模型/编排同族色」之外兼任「验收中」状态色（`.pill-review`、`.tag.t-susp` 已挂起标签），琥珀由此严格独占「等待输入」；DESIGN.md 同步新增 `pill-review` token 与分界理由。

### 修复
- **看板状态跨轮询污染**：`listAgents` 的 2.5 秒缓存此前把同一批会话对象直接交给多次调用，而看板会原地改写卡片状态（归档改 done、验收中改 review）。TTL 内的第二次轮询因此拿到「已被上一轮改过状态」的卡并按该状态直接分列，跳过归档/挂起覆盖——实测表现为挂起后卡片纹丝不动、连续刷新状态回弹。缓存改为按次返回副本。
- **催办信号收敛到验收中**：「待验收」角标只对验收中的卡生效，空闲（含已挂起）与已完成不再挂角标——此前角标按浏览器本地已读表判定、列按服务端启用基线判定，两套基线导致空闲卡「列说不用管、角标说你没看过」，挂起后的卡更是刚被你搁置就又喊待验收。仪表盘「需要你处理」改以验收中列为数据源，并区分「待验收」（没看过，琥珀）与「待处置」（看过没决定，紫罗兰），后者此前会从催办面板消失。

### 新增（工具）
- **`preview.sh` 一键验收环境**：worktree 里改完直接跑，起一套与生产完全隔离的后端 + vite dev server 并打印验收地址。高位端口（默认 37777/35173，占用自动顺延、永不绑 7777），数据用宿主库的 sqlite 快照副本——验收中的归档/挂起/改名写不回生产库，常驻实例不受影响；多 worktree 可并行验收。`--stop` 收摊、`--keep-db` 复用上轮快照。项目 CLAUDE.md 同步新增规则：worktree 开发过完质量门、交付验收前自动执行本脚本。
